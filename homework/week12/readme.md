# Week 12：計算理論的六個故事

本週整理課本《計算理論》第 1～6 章：從希爾伯特想打造「自動證明所有數學定理的機器」，到哥德爾、丘奇、圖靈證明這件事做不到，再到喬姆斯基把語言和機器分級、庫克提出 P vs NP。

| 年代 | 人物 | 主題 | 一句話 |
|------|------|------|--------|
| 1900 | 希爾伯特 | 23 個數學問題 | 數學能不能完全機械化證明？ |
| 1931 | 哥德爾 | 不完備定理 | 有些真命題就是證明不了 |
| 1936 | 丘奇 | λ-Calculus | 只用函數就能計算一切，但判斷兩函數是否相等不可解 |
| 1936 | 圖靈 | 圖靈機 | 定義了「可計算」，並證明停機問題不可解 |
| 1956 | 喬姆斯基 | 語法階層 | 四種語法剛好對應四種機器 |
| 1971 | 庫克 | SAT 是 NP-Complete | 「好驗證」的問題是否都「好解」？至今未解 |

---

## 1. 希爾伯特的問題（1900）

1900 年，希爾伯特 (David Hilbert) 在巴黎國際數學家大會提出 23 個重要數學問題。其中**第 2 問題「算術公理之相容性」**影響了整個資訊科學。

數學證明就是「公理 + 推論規則 → 定理」，例如用 **Modus Ponens（肯定前件）**：

```
P
P => Q
-------
Q
```

已知 `A`、`B` 和規則 `A=>E`、`B=>F`、`E&F=>H`，就能一步一步機械式地推出 H（課本的 `inference.py` 就是這種推論引擎）。

1920 年他提出**希爾伯特計劃**，希望整個數學：

1. **形式化**：用統一嚴格的符號和規則表達
2. **完備性**：所有真命題都能被證明
3. **一致性**：不會推出矛盾
4. **可判定性**：有演算法能判斷任何命題的真假

換成電腦的語言：**能不能寫一個程式，自動證明所有數學定理？** 接下來三章的人物，都從不同方向證明了答案是「不能」。

---

## 2. 哥德爾的定理（1929、1931）

**先有挫折：羅素悖論。** 令 `A = {x | x ∉ x}`，問 `A ∈ A`？若成立則不成立，若不成立則成立，樸素集合論因此出現矛盾，後來才用一階邏輯重建成 ZFC 公理集合論。

**完備定理（1929）**：在一階邏輯中，凡是在所有情況下都成立的式子，都證明得出來。看起來希爾伯特的夢想快實現了。

**不完備定理（1931）**：只要系統強到能描述整數的加法和乘法（皮亞諾公理），而且沒有矛盾：

- **第一不完備定理**：一定存在一句話 G，既證明不了 G，也證明不了「非 G」。
- **第二不完備定理**：這個系統證明不了「自己沒有矛盾」，直接打中希爾伯特第 2 問題。

**證明的關鍵是自我指涉**：哥德爾把公式和證明都編碼成整數（哥德爾編碼），讓算術能談論「可證明」這件事，再造出一句

> G =「這句話無法被證明」

如果 G 證得出來，系統就證明了假話（有矛盾）；所以只要系統一致，G 就證明不了，而這正是 G 說的內容，所以 **G 為真卻無法證明**。

**完備和不完備不衝突**：完備定理說的是「所有模型都成立」的式子；G 只在標準整數上成立，在某些非標準模型中不成立，所以不在完備定理的範圍內。

## 3. 丘奇的函數（1936）

丘奇 (Alonzo Church) 發明了 **λ-Calculus**，一個只有函數、沒有任何資料型態的代換系統。語法只有兩種：

1. 定義函數：`λx.M`
2. 呼叫函數：`(M N)`

運算規則也只有兩條：

- **α-conversion（改名）**：`λx.M[x] → λy.M[y]`
- **β-reduction（代入）**：`(λx.M) N → M[x:=N]`

只靠這兩條，就能用函數表示一切：

| 東西 | λ 表示法（用 Python lambda 寫） |
|------|-----------------|
| TRUE / FALSE | `lambda t: lambda f: t` / `lambda t: lambda f: f` |
| IF | `lambda c: lambda x: lambda y: c(x)(y)` |
| 數字 n（Church 數） | 把函數 f 套用 n 次：`lambda f: lambda x: f(f(...f(x)))` |
| 遞迴 | **Y-Combinator**：讓沒有名字的函數也能呼叫自己 |

有了布林、數字、遞迴，就能寫出階乘、費氏數列，所以 λ-Calculus 是 **Functional Programming 的始祖**（LISP、Haskell、Python 的 lambda 都是它的後代）。

**不可解問題**：丘奇在 1936 年證明，**不存在演算法能判斷兩個 λ 式子能否互相轉換**。也就是說，「判斷兩個函數功能是否相同」是任何程式都做不到的。

## 4. 圖靈的機器（1936）

圖靈 (Alan Turing) 是丘奇的博士生。他的出發點是：**人用紙筆計算時，到底在做什麼？**

**有限狀態機**：根據目前狀態和讀到的字元，轉移到下一個狀態，能辨識正規表達式那類的語言。

**圖靈機 = 有限狀態機 + 一條無限長的磁帶**。讀寫頭每一步：

1. 讀磁帶上目前的符號
2. 依照「目前狀態 + 讀到的符號」決定：寫入什麼、往左或往右、換成哪個狀態

這麼簡單的機器，就能計算任何「可計算」的東西，現代電腦本質上就是記憶體有限的圖靈機。

**停機問題不可解**：假設存在 `isHalt(code, data)` 能判斷程式會不會停，那就寫一個故意唱反調的程式：

```python
def U(code):
    if isHalt(code, code):   # 如果判斷「會停」
        while True: pass     #   就故意不停
    else:                    # 如果判斷「不停」
        exit()               #   就故意立刻停
```

問 `isHalt(U, U)`：回答「會停」，U 就不停；回答「不停」，U 就停。怎麼回答都錯，所以 `isHalt` 不存在。

那直接執行看看不行嗎？不行，因為程式「還沒停」時，你分不出它是**跑很久**還是**永遠不停**。

**邱奇-圖靈論題**：任何演算法可計算的東西，圖靈機都能計算；而 λ-Calculus 和圖靈機的能力完全相同。

## 5. 喬姆斯基的語法（1956）

喬姆斯基 (Noam Chomsky) 是語言學家，提出**生成語法**：用規則把一個符號展開成句子。例如：

```
S  => NP VP
NP => DET N
VP => V NP
N  => dog | cat
V  => chase | eat
DET => a | the
```

可以生成 `a dog chase the cat`。程式語言用的 **BNF** 也是同一個概念。

**喬姆斯基階層**：他把語法分成四級，剛好對應四種機器：

| 文法 | 語言 | 對應機器 | 生成規則 | 範例 |
|------|------|---------|---------|------|
| 0 型 | 遞歸可枚舉 | 圖靈機 | `α → β`（無限制） | |
| 1 型 | 上下文相關 | 線性有界圖靈機 | `αAβ → αγβ` | aⁿbⁿcⁿ |
| 2 型 | 上下文無關 | 下推自動機（有限狀態機 + 堆疊） | `A → α` | aⁿbⁿ |
| 3 型 | 正規語言 | 有限狀態機 | `A → a \| aB` | aⁿbᵐ |

越上面的語法能力越強，需要的機器也越強：

- **aⁿbᵐ**：只要記住「現在在 a 段還是 b 段」，有限狀態機就夠了（正規表達式 `a*b*`）。
- **aⁿbⁿ**：要記住 a 有幾個，需要堆疊（就像檢查括號是否配對）。
- **aⁿbⁿcⁿ**：要同時對三段計數，堆疊不夠，需要可以來回讀寫的磁帶。

而 0 型語法等同圖靈機，所以也會遇到停機問題：**有些語言是任何程式都無法正確辨識的**。

## 6. 庫克的證明（1971）

前面幾章問的是「**能不能**算」，庫克 (Stephen Cook) 問的是「**算得快不快**」。

| 類別 | 意義 | 範例 |
|------|------|------|
| **P** | 一般（確定型）圖靈機可在多項式時間內**解出**的問題 | 排序、最短路徑 |
| **NP** | 非確定型圖靈機可在多項式時間內解出；等價於答案可在多項式時間內**驗證** | 數獨、SAT、TSP 判定版 |

**非確定型圖靈機**：遇到岔路時，可以想成所有分支同時走，或是有「神諭」直接告訴你走哪條路。

**歸約 (Reduction)**：如果問題 A 能在多項式時間內轉換成問題 B，那會解 B 就會解 A。例如八皇后可以轉成整數規劃來解。

**Cook-Levin 定理：SAT 是 NP-Complete。** 證明想法是把「任何一台非確定型圖靈機的執行過程」寫成一個布林邏輯式：

- `T[i,j,k]`：第 k 步時，磁帶第 i 格是不是符號 j
- `H[i,k]`：第 k 步時，讀寫頭是不是在第 i 格
- `Q[q,k]`：第 k 步時，狀態是不是 q

再加上「每一步都符合轉移規則」「最後進入接受狀態」等限制。變數和式子都是多項式大小，所以**任何 NP 問題都能歸約成 SAT**。

**NP-Complete** 就是 NP 中最難的那群問題：只要其中**任何一個**有多項式解，**所有** NP 問題都有，也就是 P = NP。之後又有大量問題（整數規劃、TSP、圖著色……）被歸約證明也是 NP-Complete。

**P = NP?** 是千禧年七大難題之一，至今沒有人證明或否證。庫克因此獲得 1982 年圖靈獎。

---

## 總結：一條故事線

```
希爾伯特：能不能用機器證明所有數學？
   ├─ 哥德爾（邏輯）：不行，有真命題證明不了
   ├─ 丘奇（函數）  ：不行，函數是否相等不可判定
   └─ 圖靈（機器）  ：不行，停機問題不可解
           │
           ├─ 喬姆斯基：語言分四級，對應四種機器，最強的就是圖靈機
           └─ 庫克    ：就算算得出來，算不算得快？ → P vs NP
```

希爾伯特的夢想失敗了，卻意外催生出整個資訊科學：圖靈機成為電腦的理論模型、λ-Calculus 成為函數式程式語言的基礎、喬姆斯基階層成為編譯器的理論基礎，而 P vs NP 至今仍是計算機科學最大的懸案。

> 註：課本寫庫克在 1972 年提出 P=NP 問題，一般記為 1971 年（論文 *The Complexity of Theorem-Proving Procedures*）；本文採 1971。
