# 使用 opencode 和 chatgpt

第七週作業：以「字串問題」對照 **動態規劃** 與 **非動態規劃（暴力遞迴）** 兩種寫法，
計算編輯距離與最長共同子序列（LCS），最後列出執行時間並比較快慢。
程式由 opencode 撰寫、內容經 ChatGPT 討論修正，全部結果皆已實際執行驗證。

## 檔案

| 檔案 | 說明 | 複雜度 |
| --- | --- | --- |
| `dp.py` | 動態規劃版：自底向上填表，並回溯出對齊過程與 LCS 本身 | 時間 O(n·m)、空間 O(n·m) |
| `non_dp.py` | 非動態規劃版：純暴力遞迴（不填表、不記憶化），並與 `dp.py` 交叉比對答案與時間 | 指數級 |
| `big100.py` | 100 個字母的大測資：DP 直接跑、暴力遞迴設 3 秒死限中止，再用前綴實測外插估時間 | — |
| `readme.md` | 本說明 |

## 執行方式

```bash
python dp.py
python non_dp.py
python big100.py      # 約需 6 秒（暴力遞迴各題跑滿 3 秒死限）
```

## 題目說明

### 1. 編輯距離（Edit Distance）

把字串 `a` 改成 `b` 所需的**最少編輯次數**，每次只能對一個字元做插入、刪除或取代（各算 1 次）。

> 例：`kitten` → `sitting` 距離 = **3**（e→i 取代、k→s 取代、插入 g）

### 2. 最長共同子序列（LCS）

兩字串**共有的、保留原順序的最長字序列**之長度。
注意：不是「相同字母的個數」，也不用相鄰，但順序不能顛倒。

> 例：`kitten` vs `sitting` 的 LCS 是 `ittn`（長度 **4**）
> 例：`演算法` vs `演算術` 的 LCS 是 `演算`（長度 **2**）

### 3. 轉移式（兩版共用同一組）

```
編輯距離  d[i][j] = min( d[i-1][j]+1 刪除, d[i][j-1]+1 插入, d[i-1][j-1]+cost 取代 )
LCS       d[i][j] = 相同 ? d[i-1][j-1]+1 : max( d[i-1][j], d[i][j-1] )
```

差別只在**怎麼算**：`dp.py` 把這些式子填成表格、每個子問題只算一次；
`non_dp.py` 直接照式子遞迴、每次遇到都重算。

## 執行結果

四組測資的編輯距離與 LCS 長度總和 = **29**，兩版答案完全一致（全部 `True`）。

### 執行時間（`non_dp.py` 輸出，平均每次執行）

| 測資 | 題目 | 暴力遞迴 | 動態規劃 | 慢幾倍 |
| --- | --- | ---: | ---: | ---: |
| kitten → sitting | 編輯距離 | 0.2936 ms（2763 次呼叫） | 0.0069 ms | 42.7 |
| kitten vs sitting | LCS | 0.0471 ms（446 次呼叫） | 0.0050 ms | 9.4 |
| algorithm → altruistic | 編輯距離 | 4.5179 ms（42767 次呼叫） | 0.0133 ms | 339.5 |
| algorithm vs altruistic | LCS | 0.4026 ms（3708 次呼叫） | 0.0092 ms | 43.7 |
| **四組總計** | — | **5.7081 ms** | **0.0518 ms** | **110.3** |

| n | 暴力編輯 | DP 編輯 | 慢幾倍 | 暴力 LCS | DP LCS | 慢幾倍 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 0.0134 ms | 0.0031 ms | 4.3 | 0.0052 ms | 0.0022 ms | 2.3 |
| 5 | 0.0493 ms | 0.0046 ms | 10.7 | 0.0138 ms | 0.0030 ms | 4.5 |
| 6 | 0.2056 ms | 0.0061 ms | 33.9 | 0.0356 ms | 0.0041 ms | 8.7 |

| 8 | 4.1706 ms | 0.0101 ms | 414.9 | 0.3314 ms | 0.0070 ms | 47.2 |

可看到：DP 的時間隨 n **平方成長**（n 加 1 只多填一列一欄），暴力遞迴則**指數爆炸**，
n 從 4 到 8 時間成長約 300 倍，差距只會越來越大。

### 100 個字母大測資（`big100.py`）

測資：`random.seed(7)` 產生兩串各 100 個字母（a–z），`b` 由 `a` 改動 25 個位置而成。
答案：編輯距離 **24**、LCS 長度 **76**。

| 方法 | 編輯距離 | LCS |
| --- | ---: | ---: |
| 動態規劃（101×101 = 10201 格） | **1.3041 ms** | **0.9093 ms** |
| 暴力遞迴（3 秒死限） | 跑滿 3.00 秒、呼叫 20,180,992 次仍沒結果 → 放棄 | 跑滿 3.00 秒、呼叫 13,987,840 次仍沒結果 → 放棄 |

因為暴力在 n=100 根本跑不完，改用前綴實測看它的成長速度（答案皆與 DP 相同）：

| n | 暴力編輯呼叫 | 暴力編輯 | 暴力 LCS 呼叫 | 暴力 LCS |
| ---: | ---: | ---: | ---: | ---: |
| 10 | 59 | 0.0069 ms | 32 | 0.0036 ms |
| 12 | 911 | 0.1024 ms | 228 | 0.0265 ms |
| 14 | 11,673 | 1.3700 ms | 1,500 | 0.1728 ms |
| 16 | 214,672 | 24.2844 ms | 12,234 | 1.3702 ms |

再用最後 3 筆（n = 12、14、16）的指數成長率外插回 n = 100（僅供估算）：

| 題目 | 估計呼叫次數 | 估計耗時 | 比 DP 慢 |
| --- | ---: | ---: | ---: |
| 編輯距離暴力 | 約 1.3×10⁵⁵ 次 | 約 4.8×10⁴⁰ 年 | 10⁵¹ 倍 |
| LCS 暴力 | 約 2.5×10⁴⁰ 次 | 約 8.8×10²⁵ 年 | 10³⁶ 倍 |
| **動態規劃** | 10,201 格 | **1.3 ms / 0.9 ms** | 1 |

（宇宙年齡約 1.4×10¹⁰ 年，暴力遞迴所需的時間遠遠超過它；DP 只要 1 毫秒多。）
這就是動態規劃的價值：把**指數級**變成**平方級**。

## 兩種方法的優缺點

### 動態規劃（`dp.py`）

| | 內容 |
| --- | --- |
| 優點 | 1. 時間 O(n·m) 穩定可預測，資料再大也不會爆掉 |
| 優點 | 2. 每個子問題只算一次，沒有任何重複計算 |
| 優點 | 3. 填完表可**回溯**出完整解（對齊的每一步、LCS 字串本身），不只是一個數字 |
| 優點 | 4. 結果可重現、與輸入順序無關，方便除錯 |
| 缺點 | 1. 需要 O(n·m) 記憶體存表（可用滾動陣列壓到 O(m)，但就不好回溯） |
| 缺點 | 2. 必須先想出正確的轉移式與邊界條件，想錯就全錯 |
| 缺點 | 3. 程式碼較長，需另外寫回溯段落 |

### 非動態規劃／暴力遞迴（`non_dp.py`）

| | 內容 |
| --- | --- |
| 優點 | 1. 直接照轉移式寫，程式最短、最好懂，最適合當「暴力正確解」驗證答案 |
| 優點 | 2. 不需另外開表格，記憶體只有呼叫堆疊 |
| 優點 | 3. 輸入很短或兩串幾乎相同時（早早命中 base case）反而最快，如 `演算法→演算術` 只要 6 次呼叫 |
| 缺點 | 1. 大量重複計算，時間**指數成長**：n=8 就慢了 415 倍，n=100 估計要 4×10⁴⁰ 年（`big100.py`） |
| 缺點 | 2. 沒有表格可回溯，通常只能得到長度，得不到實際的解 |
| 缺點 | 3. 遞迴太深可能爆掉堆疊；呼叫次數無法事先估準 |

> 暴力遞迴之所以「不是動態規劃」，是因為它**沒有記憶化**。
> 若在遞迴時把算過的 `d[i][j]` 存起來，就變成 top-down（自頂向下）的 DP，
> 時間同樣會變成 O(n·m)——這正是 DP 的核心：**把重複子問題記住**。
